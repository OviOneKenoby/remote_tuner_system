# Coordination execution rules

- Read README.md, PROJECT_SYNC.md, API_STATUS.md, DECISION_REGISTER.md and both latest handoffs before a task. Record the coordination commit read.
- Preserve all initial project facts. Missing evidence means UNKNOWN or NOT VERIFIED, never PASS.
- Do not change shared contracts unilaterally. Follow README contract approval procedure. PM task assignment is not owner contract approval.
- Execute only the assigned device scope and accepted task. Unassigned draft tasks are not execution authorization.
- Use templates/HANDOFF_TEMPLATE.md exactly: retain all headings and fill every field. Write explicit NONE, UNKNOWN, NOT RUN or NOT APPLICABLE with reasons instead of blanks.
- Archive the prior latest handoff before replacement; never edit historical archives.
- Record verification command/procedure, environment, result and evidence location. Build, simulation and physical hardware evidence are distinct.
- Update the device changelog and this coordination CHANGELOG for actual changes. Check prior fixes before repeating work.
- Do not edit synced/read-only references. Use approved, versioned references and flag stale candidate headers.
- Publish changes without overwriting concurrent work. Pause dependent implementation when a contract or evidence gate is unresolved, and report the blocker.
