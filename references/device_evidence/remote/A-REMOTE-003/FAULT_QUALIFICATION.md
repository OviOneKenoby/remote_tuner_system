## Exact safety counterexample / missing guarantee

Fixture initially has no effect and allocator pair0. New checkpoint stores fixture() with intent:1, pair1, unresolved TARGET+RESOURCE barriers; independent oracle records one simulated emission. Restore ONLY original valid anchor bytes; both banks remain. That older SEALED anchor and bank pass CRC/digest/canonical validation. Decoder returns the older no-effect/pair0 projection. Thus valid-old-anchor recovery cannot distinguish rollback from a legitimately older current state. Recovery itself still emits zero, but future unblocking would lose non-reuse/barrier obligations. Test `test_stale_valid_anchor_counterexample_not_certified` records OLDER_VALID_PROJECTION_INDISTINGUISHABLE / PRODUCTION_QUALIFICATION_BLOCKED.

This is an adversarial fake-backend guarantee gap, NOT a demonstration that physical IDF/NVS actually performs this rollback. A missing/corrupt anchor is safely blocked, not allowed to fall back. The pinned source does not establish an independent durable newest-intent marker or a multi-key transaction. Readback/nvs_commit cannot certify abrupt-power-loss behavior. Consequently the blanket fail-closed PREPARE/SEALED claim is not qualified for production. Do NOT use strategyA or silently select an older bank.
