# Proposed staged migration and operational rollback
NOT IMPLEMENTED / NOT AUTHORIZED FOR DEVICE EXECUTION. CCM1.1.0 G1a REQUIRED, G1b OUTSIDE only for intentional complete coherent restoration. Losing newer barriers via intentional old-image restore is not an acceptable operational downgrade. No production durable state presently proven; in-memory MockJournal is not a trustworthy migration source. remote_wifi stays untouched in default nvs; no credential copying, default-NVS erase or enlargement.

## Deployment blocker before data migration
Current primary partition table is a single sector at0x8000; its MD5 detects invalid/torn tables but does not make erase/write atomic or supply a second bootable table. Existing bootloader rollback option disabled. Normal application OTA changes an inactive app/otadata, not a qualified crash-safe table switch. SDK documents partition-table/data/bootloader updates as unsafe when interrupted. Generation/commit barriers inside remote_ctl cannot repair a torn primary table before the bootloader finds the application. There is NO proven self-resuming boot path for a power cut during this sector rewrite. This is an explicit blocker, not a false claim that every step automatically reboots safely.

Before any deployment, separately qualify one of: a bootloader/redundant-table strategy with crash-safe selection (new reviewed firmware/bootloader work), or a precisely authorized maintenance/recovery route using known bootloader/ROM access and verified preserved backups, controlled installation and qualified interruption recovery. Stable supply alone is a risk reduction, not G1a proof. Recovery host/device operations require separate authorization; not executed here. Generic PlatformIO full upload can overwrite otadata/bootloader and bypass required preservation, so no ready-to-run upload command is proposed.

## Exact stage/authority model
M0 discover/verify installed16MiB flash, bootloader/table hash, active slot, old image, reset/security policy, all occupied tail ranges; securely preserve/verify necessary existing data off-device under separate permission. Log hashes only in public coordination, never credentials.
M1 install a separately qualified bridge in inactive existing slot with **emission disabled**, old/new schema readers and fail-closed startup. Preserve current table/nvs/otadata until a qualified boot-selection policy permits change; health-check bridge and retain last safe image. Current unmodified old firmware is NOT that bridge.
M2 perform only the separately qualified primary-table installation route; add remote_ctl descriptor, no existing offsets/sizes change. Verify installed full table, apps and original nvs unchanged. On invalid/torn table, recover by the qualified boot/maintenance path; do not continue to M3. If no proven path, migration stops atM1.
M3 validate target range ownership/erased or compatible contents, schema/version/capacity; initialize **only** remote_ctl under explicit permission. Unexpected nonblank data or unknown schema block, never format to "repair". Confirm remote_wifi remains available without publishing values.
M4 quiesce all control mutations/emission, snapshot a verified accepted source history including allocations/non-reuse, requests/effects/attempts/correlation/unresolved barriers/proofs. Since current durable source absent, fail closed unless separately approved complete reconciliation/fencing establishes the initial accepted history. No invented empty state may erase uncertain executions. Write generation g prepared BASE/ALLOC/PROOF records in new storage with complete immutable context and content validation, retaining all source data. No authority change yet.
M5 scan/read back/validate prepared generation, proof/record links and capacity at full overlap. Durability ordering/acknowledgement must be qualified, not inferred from nvs_commit. Persist root generation-g commit record referencing full validated data; ambiguity retains affected-scope block.
M6 commit new-authority ownership with an explicit version/epoch and correlation between durable root and migration authority marker under a **single serialized, recoverable protocol**. Exact storage format/atomic selection mechanism is a required next design deliverable, not supplied by current NVS CAS. All disagreement/uncertain ordering blocks; no fallback to older valid root. This is the conservative **downgrade incompatibility cutoff**: once new authority may have committed, raw predecessor without new schema/history support cannot execute control safely, even before first emission. Preserve old source/archive only as evidence, not as a competing writer. Bridge stays emission-disabled until deterministically accepted ownership.
M7 allow new-epoch work only after complete recovery and authorization; append durable admissions/effect/barrier state before emission; allocator values never reused in accepted history. Independent witness in qualification remains outside faulted domain. A late proof resolves only its correlated historical scope; no replay or barrier deletion due to upgrade.
M8 compact only when lossless mandatory retention and at least GC/old-new/proof margin are proved. Do not erase original nvs or downgrade schema. Unknown proof growth/capacity exhaustion refuses before emission. Legacy source archival retirement, if ever allowed, is a separate reviewed step.

## Operational return path
BeforeM6 (and only if ownership is determinably old), stop migration and return via qualified bridge/old-code path with verified unchanged source and inhibited unsafe emission. AfterM6 or uncertainM6, roll **code** back only to a compatible bridge/recovery image that understands retained new schema/history, keeps command emission disabled until reconciliation, and preserves new partition/data. Old factory firmware may remain bootable at unchanged address but is not a valid control rollback target without this qualification. Boot old code only for UI/maintenance if its emission inhibition is demonstrably enforced; current predecessor not proven, so default refuse.

Do not revert the primary table/remove remote_ctl, erase new history, reset generations, or restore an old flash/NVS image as operational rollback. Partial restores/stale roots remain G1a fail-closed cases. A complete coherent adversarial restoration is G1b OUTSIDE and cannot be relabelled operational PASS. Owner must accept deployment/recovery mechanism and downgrade cutoff before any implementation/device operation; capacity approval alone is insufficient.

## Proposed migration record identity and extra capacity gate
A future explicit MigrationIntent must identify migration_id, source schema/accepted-history hash and generation, destination schema/generation, immutable manifest of all mandatory record hashes, ownership state PREPARED or ACTIVE, predecessor root hash, and integrity/version metadata. PREPARED is never an emission authority. ACTIVE must reference a fully validated committed root and quiesced prior writer; differing markers/root/record manifests or unknown outcome block. Publish ACTIVE only through a separately qualified single-writer ordered commit protocol; no assumption of atomic writes across default nvs and remote_ctl. Recovery never dispatches and never chooses a marker solely because its generation/checksum is largest. These are proposed closed semantic fields; exact binary encoding and interrupted-operation commit decision rule remain required in A007 design, not invented as implemented guarantees.

The948/1222 entry comparisons cover declared P4 storage/update/compaction. Extra migration intent, backup/snapshot overlap, bridge metadata and transitional proof growth must be explicitly encoded and budgeted before rollout. Current source has no complete persistent accepted history; feasibility of that initial snapshot is UNKNOWN. Spare entries are margin, not proof that arbitrary migration records fit. Retain all source/new records until ACTIVE ownership and rollback-compatible reader have been proven; no premature reuse of source generations/records.
